# SQL Portfolio: Analytics for a Ceramic Raw-Materials Business (PostgreSQL)

Two self-contained SQL projects on realistic, synthetic data from the ceramic industry. Each project has its own README, data, scripts in numeric order and exported results.

> **All data is synthetic.** It is generated by the `src/generate_data.py` script in each project (fixed seeds) and imitates the structure of ERP and sales extracts. No real company data is used.

| Project | Question | Main techniques |
|---|---|---|
| [`purchasing-data-cleaning`](purchasing-data-cleaning) | Where does raw-material spend go, and how do we get reliable figures from a messy extract? | Anti-joins, CTE cascades, `RANK()`, NULL audit with `jsonb_each_text`, imputation with fallback chain, leave-one-out back-test, `LAG()` |
| [`wholesale-net-revenue`](wholesale-net-revenue) | What is wholesale net revenue after payment fees by product line, month and warehouse? | `GROUP BY` with `date_trunc`, unit-aware calculation, window functions over aggregates, `ASSERT`-based checks |

## How to Run

Requirements: Docker with Compose (PostgreSQL 16 runs in a container; nothing is installed locally).

```bash
bash run_all.sh                          # all projects
bash run_all.sh wholesale-net-revenue    # a single project
```

`run_all.sh` starts the database and executes every `sql/0*.sql` script of the selected projects in order. Results appear in each project's `output/` folder. Without bash, start the database with `docker compose up -d --wait` and run the scripts one by one as shown in the project READMEs.

To regenerate a dataset, install `requirements.txt` and run `python src/generate_data.py` inside the project folder.

## Conventions Used in Both Projects

- Scripts are numbered and idempotent (`DROP ... IF EXISTS` before `CREATE`), so any project can be re-run from scratch.
- Analyses are exposed as views (`v_*`), and `\copy` exports the views to CSV, so SQL stays the single source of truth.
- Every correction to the data is traceable: imputed values keep their source, rejected rows are flagged rather than deleted.
- Calculations that depend on units or on the meaning of a column (percentages, standard cost) are documented where they happen.
